BALI VILLA ACCOUNTING SEO BLUEPRINT
Implementation brief for bali-villa-accounting-service.com
Audit date: 5 October 2026
Prepared for David Dandanell

Purpose

Increase qualified enquiries from Bali villa owners and operators by fixing the current website failures, making useful content reliably crawlable, and building a focused set of service and evidence pages. Keep the site's English language and its current bookkeeping scope. Treat the proposed keywords as intent hypotheses until Search Console and keyword research validate demand. This is an implementation plan, not a forecast of rankings or leads.

The largest opportunity is a stronger website structure and a working conversion path. The existing homepage already has a relevant title, a substantial amount of topical copy, prices, contact information, and AccountingService structured data. Adding more synonyms to that page alone is a low priority.

Where: All buttons using the shared clarity-call handler.
Evidence: Clicking the hero booking button opened https://calendly.com/villabooksbali/clarity-call in a new tab. That tab displayed Calendly's 404 page. The deployed handler uses this same destination for the clarity-call buttons.
Action: Replace the destination with an active event owned by the business. Until the correct event is available, offer a clear consultation request through the existing verified contact channel. Prefer a normal anchor link for navigation to an external booking page.
Acceptance: A customer can reach an active event, see availability, select an appropriate timezone, and reach the booking form. Staff validate final test submission internally; do not create a real customer appointment without authorization.
Owner: Developer and business owner. Effort: small after the correct link is supplied.

P0  Blog content fails to load
Where: /blog and the homepage latest-guidance section.
Evidence: /blog displayed an error state and retry did not restore the list. The public GET /api/blog/posts?limit=50 returned HTTP 500. The homepage displayed its refreshed-guides fallback.
Action: Diagnose the real backend exception, deployment configuration, database/query access, and response contract. Do not conceal the problem by substituting invented articles. Serve the last successfully published public content where possible. Keep private configuration and error details out of public responses.
Acceptance: The article list returns the expected data; real published articles render, refresh successfully at their direct URLs, and link to related services. An empty state is distinguishable from a server failure. A temporary outage does not erase previously published content from the public site.
Owner: Developer. Effort: requires backend diagnosis.

Acceptance: Fetching each route without running JavaScript returns the correct head tags, and rendering does not change the canonical to a different URL. Test article routes once the blog works.
Owner: Developer. Effort: medium with the rendering work below.

11. MEASUREMENT AND DECISION RULES

Baseline before implementation

1) Verify ownership in Google Search Console and review indexing, sitemaps, security/manual-action notices, and representative URL Inspection results.
2) Export query and page performance for the longest useful available period, ideally including up to 16 months for seasonality.
3) Separate brand searches from non-brand service searches. Review countries and device types because foreign villa owners may search from outside Indonesia.
4) Record current organic enquiries, qualified enquiries, booked consultations, and signed clients if the business tracks them.
5) Audit the current analytics tool. The deployed Umami call is not proof that events are collected. Retain or repair a suitable existing system instead of automatically installing duplicate trackers.

Recommended event model

whatsapp_click: page, placement, and relevant service or package.
phone_click: page and placement.
consultation_click: page and CTA destination.
consultation_booked: successful booking, only if confirmed by the booking system or an approved integration.
enquiry_submitted: successful form submission, not merely pressing the button.
sample_report_view or download: engagement with the actual report resource.
qualified_lead: staff-verified relevant enquiry in the CRM or lead log.
client_won: actual signed client and attributable source where available.

Do not include names, emails, phone numbers, bank details, or message bodies in analytics events. Preserve source attribution through forms and booking flows without putting personal data into URLs. WhatsApp clicks are useful intent signals; they are not confirmed conversations or qualified leads.

Review logic

- Not indexed: investigate crawlability, response, canonical, rendering, content value, and discovery.
- Indexed with few impressions: reassess intent, demand, usefulness, relevance, and authority.
- Impressions with low CTR: compare the page's query mix and search presentation before testing title and description changes.
- Traffic with few enquiries: improve offer clarity, proof, price explanation, contact reliability, and form friction.
- Many enquiries but weak fit: tighten the audience, qualifications, package scope, and CTA wording.
- Pages overlapping: inspect query-by-page performance and content purpose before consolidating.

Review 28-day trends together with longer windows and seasonality where possible. Annotate release dates. Avoid assigning causal credit to one title change when a full site rebuild occurred at the same time. Judge success primarily on relevant enquiries and clients, supported by discovery, impressions, clicks, CTR, and page-level query coverage.
