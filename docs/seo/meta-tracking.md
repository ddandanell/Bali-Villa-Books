# Metadata and measurement contract (site-001)

Owner: Adel (Bali Accounting SEO). Last updated 2026-10-31.

## Why this exists

The build must not ship a page whose head is wrong. Before this gate, the only checks
were manual: titles, descriptions, canonicals, Open Graph images and FAQ schema were
inspected by eye after each deploy. The comparison cluster added five commercial pages
in one release, so the contract is now enforced by code.

## The contract, per route

Each social/commercial route in `lib/site-content` + `sitePages` must ship:

| Element | Rule | Severity |
| --- | --- | --- |
| `<title>` | present, unique, 15–65 characters | error / warning on length |
| `meta description` | present, unique, 70–165 characters | error / warning on length |
| canonical | exactly one, equal to `https://bali-villa-accounting-service.com<route>` | error |
| robots | indexable; `noindex` only on the 404 document | error |
| `<h1>` | exactly one | error |
| Open Graph | `og:title`, `og:description`, `og:url`, `og:image` (on-origin, file exists), `twitter:card`, `twitter:image` | error |
| JSON-LD | parses, includes `BreadcrumbList` (except `/`), plus `FAQPage` wherever FAQ blocks render | error |
| body copy | at least 300 words rendered | error; warning under 600 |
| FAQ parity | on-page `<details>` count matches a `FAQPage` node | warning |

`scripts/src/seo-audit.mjs` writes `docs/seo/meta-audit.json`, a tracked snapshot. A
metadata change therefore appears as a reviewable diff rather than an invisible edit.
It runs inside `pnpm run build:web` after prerendering, so Vercel refuses to promote a
build with a broken head. Run it alone with `pnpm --filter @workspace/villabooks-bali run seo:audit`.

## Link checking

Every internal `href` in the built HTML must resolve to a file this build wrote.
`/api/*`, `/blog*` and `/sitemap*` are served at runtime by the journal origin and are
skipped by the offline check; `/blog/<slug>` targets are verified separately against
production before release (17 checked on 2026-10-31, all 200).

## Sitemaps

- `sitemap.xml` — the journal origin's list. Not generated here, not edited here.
- `sitemap-journal.xml` — articles this build renders from `journal-static.ts`.
- `sitemap-pages.xml` — every marketing route this build writes, with `lastmod` from the
  build date. Generated by `prerender.mjs`; the audit fails if a route is missing.

## Measurement

What exists today:

- First-party events via `POST /api/site-events` (proxied by the Vercel gateway to the
  journal origin). Allowed: `whatsapp_click`, `phone_click`, `consultation_click`,
  `enquiry_submitted`, `sample_report_view`, `sample_report_download`, `blog_view`,
  `article_completion`. Payload: `eventType`, `page`, `placement`, optional `service`.
  No personal data, no query strings, no session identifiers.
- Page paths are allowlisted client-side; comparison routes were added to that
  allowlist on 2026-10-31 so their CTA clicks are attributed to the page, not
  `other_page`.

What does not exist, and must not be implied in reporting:

- No Google Search Console or GA4 access for this site.
- Vercel Web Analytics is not enabled on the project (`webAnalytics: false`).
- The Umami script is injected by the journal origin at publish time; a page served as a
  static file from this build does not necessarily receive it. CTA events still record
  first-party.

Funnel stages, kept separate in any report: local page views → CTA clicks (`whatsapp_click`,
`consultation_click`) → enquiries delivered (`/api/enquiries`) → qualified leads →
revenue. None of the later stages is currently instrumented end to end, so no conversion
rate is claimable.

## Adding a page

1. Add the route to `sitePages` (or the relevant content module) with title and description.
2. Add an entry to `lib/site-content/src/page-imagery.json` — the build fails on drift.
3. Add the route to `App.tsx` and to the client-side analytics path allowlist.
4. Add internal links from at least two existing pages; the cluster must not be orphaned.
5. Build. `seo-audit` must report zero errors before the commit is pushed.
