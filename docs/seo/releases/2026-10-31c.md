# Release 2026-10-31c — journal asset aliases

## Defect

Every journal URL on the public domain returned markup built by the Replit origin that referenced
`/assets/index-DNBcDR-U.js` and `/assets/index-Cpd-dkeJ.css`. Both return 404 from this deployment,
so a reader — and a crawler — received a page with no stylesheet and no bundle.

Measured at 2026-10-31T05:46Z, redirects not followed:

| URL | Status | Bytes | md5 |
| --- | --- | --- | --- |
| `https://bali-villa-accounting-service.com/blog` | 200 | 102,492 | `022bca7b2769b2f7d0fc805aadba99d6` |
| `/blog/airbnb-reserves-delayed-payouts-bali-villa-bookkeeping` | 200 | 33,956 | `df6e658130cb85290b9f59e559e32b52` |
| `/assets/index-DNBcDR-U.js` | 404 | — | — |
| `/assets/index-Cpd-dkeJ.css` | 404 | — | — |
| `/assets/index-pdc3_Fz2.js` (this build) | 200 | 729,626 | — |

The same documents at `bali-villa-books.replit.app` carry the same dead pair, so the fault is in the
origin's build, but it is served on the apex because `vercel.json` rewrites `/blog` and `/blog/:path*`
to `api/gateway.mjs`.

## Change

1. `artifacts/villabooks-bali/prerender.mjs` copies this build's real JS and CSS to stable aliases
   `/assets/app.js` and `/assets/app.css`, and writes `journal-assets.json` recording which hashed
   files they came from. No hash is hardcoded; it is read from the built `index.html`.
2. `api/gateway.mjs` rewrites `/assets/index-<hash>.{js,css}` references in proxied HTML documents to
   those two aliases. Nothing else in the origin's document changes. Exported as `repointAssets` so it
   can be tested without a server.

Verified against the live origin before merge, at 2026-10-31T05:49Z: `/blog` 102,459 bytes and the
Airbnb article 33,888 bytes, each with both references replaced and no `index-` reference left.

## What this does not fix

- It does not rebuild the origin, and it does not remove the two 404 requests from anyone still
  holding the old URL. It stops the site from asking for them.
- It does not fix the content differences between the origin's older build and this one. Hydration is
  now possible on those documents for the first time; the client bundle is this build's, so the page
  may re-render after load. Content is server-rendered in the document either way.
- The durable fix is still to serve the journal from this build's prerendered pages, or to redeploy
  the origin from the same commit. This entry is the interim bridge and should be deleted when either
  lands.
