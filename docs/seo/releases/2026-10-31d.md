# Release — 2026-10-31d — journal asset aliases: drop the year-long cache

Site: bali-villa-accounting-service.com · repo `ddandanell/Bali-Villa-Books`
Written 2026-10-31 14:08 (+08) / 06:08Z. Merged as `3be67564` (PR #15), head `2fb5160f`.

## Finding (Independent QA Reviewer, post-release smoke check of `3624a057`)

`/assets/app.js` and `/assets/app.css` are stable, unversioned URLs. `vercel.json` served everything
under `/assets/(.*)` with `Cache-Control: public, max-age=31536000, immutable`. Measured on the apex
before this change:

| URL | Cache-Control |
| --- | --- |
| `https://bali-villa-accounting-service.com/assets/app.js` | `public, max-age=31536000, immutable` |
| `https://bali-villa-accounting-service.com/assets/app.css` | `public, max-age=31536000, immutable` |

`prerender.mjs` re-copies each build's hashed bundle to those same two URLs, so a returning visitor
who fetched the alias once could keep the previous build's JS and CSS for up to a year while receiving
new HTML — the stale-bundle class of fault the alias was introduced to remove, inverted. Hashed files
(`/assets/index-<hash>.{js,css}`) are unaffected and keep the immutable header, which is correct for
content-addressed names.

## Change

Two `headers` rules in `vercel.json`, placed after the `/assets/(.*)` rule so they take the same
`Cache-Control` key for last-match precedence:

- `/assets/app.js` → `public, max-age=0, must-revalidate`
- `/assets/app.css` → `public, max-age=0, must-revalidate`

No build, bundle or gateway code changed.

## What this does not fix

- It does not version the alias. Prerender still writes two fixed names; the durable fix is a
  content-addressed alias (`app-<hash>.js`) or serving the journal from this build's prerendered
  pages. `blog-seo.ts` at the origin still emits the old hashes upstream, so the gateway repoint
  remains an interim bridge until the Replit app is redeployed or the journal moves into this build.
- The two dead filenames remain 404 for anyone holding the old URL; nothing served can recover them.
