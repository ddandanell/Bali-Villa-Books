## Why

`/faq` carried 16 internal links whose entire visible text was **Read more**, each pointing somewhere different (`/pricing`, `/villa-financial-reporting-bali`, `/villa-bookkeeping-cleanup-bali`, `/airbnb-bookkeeping-bali`, `/tax-compliance-bali`, `/get-started`, `/company-formation-bali`, `/investor-kitas-bali`, `/services`, `/blog/bali-villa-chart-of-accounts`, `/pt-pma-villa-bookkeeping`).

This was already recorded as a must-fail: shared engine run `2026-10-31T081102Z`, `LINK-003`, message "16 non-descriptive internal anchors", evidence `Read more | Read more | Read more`. The repo build gate did not check anchor text, so a document the engine fails passed the build.

A link that does not name its destination is unusable to a reader scanning for a next step, and it gives the destination no anchor signal. The house rule and the coded rule already agree; only the enforcement was missing.

## What changed

`artifacts/villabooks-bali/src/lib/additional-faqs.ts`, `src/pages/PageContent.tsx`

1. The FAQ tuple gains an optional fourth element, the link label. One array still drives both the visible FAQ and the `FAQPage` schema (`page-document.ts` reads the first two elements only, so the schema is untouched).
2. All 16 hrefs carry a label naming the destination, varied rather than one repeated phrase — "See what each monthly package includes" → `/pricing`, "See how Airbnb payouts are reconciled" → `/airbnb-bookkeeping-bali`, "See the villa chart of accounts" → `/blog/bali-villa-chart-of-accounts`, and so on.

`scripts/src/seo-audit.mjs`

3. The gate now enforces `LINK-003`: any internal anchor whose whole text is generic (`read more`, `read this`, `learn more`, `find out more`, `see more`, `more`, `details`, `click here`, `here`, `this page`, `this link`, `link`, `continue reading`, `go`) fails the build, naming the anchor and the target.

## Proof the gate can fail

One generic anchor injected into the built `/faq` document, then the audit run:

```
seo-audit: FAIL — 29 documents, 1 errors, 2 warnings
  ERROR /faq: 1 non-descriptive internal anchor(s), LINK-003: "Read more" -> /pricing
```

Exit code 1. Document restored by rebuilding. A gate that cannot fail is decoration, so this was tested before the merge, not assumed.

## Not fixed here, stated rather than papered over

1. **Two redirect hops remain.** `/blog/indonesia-emergency-stay-permits-krakatau-september-2026` links to `/blog/bali-villa-expense-tracking-system`, and `/blog/indonesia-foreign-worker-permits-oss-september-2026` links to `/blog/bali-villa-supplier-invoice-payroll-bpjs-control-calendar`. Both 308 to a 200 via `vercel.json`, so no reader and no crawler hits a 404. The hrefs live in article bodies held by the journal backend, so rewriting them means a content edit there or a fifth edge transform — neither is proportionate to a single hop that already resolves.
2. **A third redirect has no live inbound link.** `/blog/bali-villa-owner-monthly-report` 308s to `/blog/bali-villa-owner-statement-template` but nothing on the site links to it. Kept as a safety net; not a defect.
3. **`FAQPage` mirrors 10 of the 22 visible FAQs on `/faq`.** The schema is built from `additionalFaqs` only, so the 12 questions defined locally are visible but not in structured data. Pre-existing, unchanged by this release, and not a LINK rule — it needs its own decision about whether the schema should mirror the full set.
4. **A bug I made and caught before building.** The first patch replaced four hrefs with labels instead of adding a fourth element, dropping `/company-formation-bali`, `/investor-kitas-bali`, `/blog/bali-villa-chart-of-accounts` and `/pt-pma-villa-bookkeeping` from their entries. The pre-build check of the tuple arity found it; the shipped entries all carry both. No build was run against the broken version.
5. **No independent QA PASS on this commit.** Merged under David's no-holding instruction and recorded as unreviewed-at-merge. QA has the diff and the live check above.
