## 5. Correction, 2026-10-31 18:40 (+08)

Section 3 above said the full crawl showed "0 non-200, 0 orphans, 0 dead ends". The 0 non-200 and 0 dead ends are correct. **The orphan count was wrong for the new article.**

Checked directly after the release: `/blog/pt-pma-annual-corporate-tax-return-records-bali` had **zero inbound internal links** in any document. It was in `sitemap-journal.xml` and it linked out, but nothing linked in. Cause: `/blog` is not prerendered from this build — it is proxied to the origin, which renders the older app whose journal list comes only from `/api/blog/posts`, and static build articles are not in that API. The `latestStatic` block in this repo's own `Blog.tsx` never runs, because that page is not the one being served.

So the "0 orphans" figure came from my crawl script counting targets, not from checking the new page specifically. The release record is corrected here rather than left standing.

Fix in this same release: `SeoTopicGuides` (rendered on every marketing page that has a topic cluster) now appends the three newest static journal articles. Verified in the prerendered build: the new article is linked from 11 prerendered documents — `/`, `/services`, `/pricing`, `/faq`, `/get-started`, `/sample-report`, `/pt-pma-villa-bookkeeping`, `/villa-financial-reporting-bali`, `/villa-bookkeeping-cleanup-bali`, `/airbnb-bookkeeping-bali`, `/tax-compliance-bali`.

This is a self-maintaining fix: every future daily article is linked from those pages the moment it is built, with no edit to the link map. It does not fix the journal hub, which remains origin-rendered.
